把 Xiaomi-OCR-0 官方 Demo 改成一键启动的本地 App

编程2026-11-27

前一篇介绍 Xiaomi-OCR-0 时，结尾跑的是官方自带网页 Demo——能跑，但启动前要折腾一长串：建 venv、装依赖、手动 export 三个环境变量、记住端口号。想「双击就用」的人不会喜欢这个流程，所以我动手把官方 demo/ 重做成了一个自包含 App：xiaomi-ocr-0-demo-app——打开即用，什么都不用填。

从一串命令到 ./run.sh

官方 demo 的启动流程（上一篇里原样贴过）：

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
export XIAOMI_OCR_BACKEND=ollama
export XIAOMI_OCR_MODEL=longwayxu/xiaomi-ocr-0:bf16
export XIAOMI_OCR_LOCAL_URL=http://127.0.0.1:11434/v1
python demo/server.py --port 8787

现在整个仓库克隆下来，只要一条命令：

git clone https://github.com/mengfei523060/xiaomi-ocr-0-demo-app
cd xiaomi-ocr-0-demo-app
./run.sh        # 首次自动建 venv + 装依赖，然后直接起服务并打开浏览器

run.sh 首次运行自动创建 .venv 并装 core/requirements.txt——只有 Pillow、pypdfium2、numpy 三个包：推理全走本机运行时，服务端连 openai SDK 都不需要。默认 http://127.0.0.1:8790 并自动弹浏览器；端口如果被占，已有本 App 实例就提示打开现有地址，否则提示换端口。Windows 没有 bash 也能跑：python app\server.py --port 8790 --open 一条命令等价。

模型零配置：App 自己找运行时

官方 demo 要手动 export 后端、模型名、URL 三件事；App 里这些全没了，启动时自动按优先级探测：

  1. 本机 :8190 已有 llama-server 在跑 → 直接接入，模型名问它自己；
  2. Ollama 里有名字含 xiaomi-ocr-0 的模型 → 走 Ollama 原生通道；
  3. 装了 llama.cpp → App 用内置 GGUF 自动在 8190 拉起 llama-server（Ctrl+C 退出时只停自己拉起的，不误杀你手动开的）；
  4. 只有 Ollama 没模型 → 用内置 Modelfile 一键导入为 xiaomi-ocr-0:app，与已 pull 的官方模型 blob 去重，秒级完成。

「内置 GGUF」指仓库 model/ 目录打包了 Xiaomi-OCR-0 0.8B BF16 的 GGUF + 视觉 mmproj（约 1.7GB，MANIFEST.json 带 sha256 校验）。这两个大文件不入库，git clone 只有几 MB；用 Ollama 的用户则完全不需要它们。界面顶部状态行会实时显示接入情况：「使用内置模型 · 正在加载…」，绿点亮了直接拖图；缺什么也直接提示缺什么，绝不后台下载任何东西。

功能一样不少，PDF 更好用

  • 文档解析：整页转 Markdown，OTSL 表格还原成 HTML、公式带 LaTeX 渲染——前端自带 KaTeX，离线可用；
  • 字段提取（KIE）：逗号分隔字段名，出 JSON 键值表；图像问答（VQA）照旧；
  • PDF 整本解析：pypdfium2 逐页渲染、并发 OCR、SSE 实时进度 + 缩略图、可中途取消、空白页自动跳过，导出 .md；
  • 结果三视图（预览 / 原文 / JSON）、一键复制下载（浏览器本地生成文件名，失败走服务器兜底）、内置 7 个样例（小票、论文公式、书法、手写公式、KIE、VQA）、⌘/Ctrl + Enter 快捷键；
  • 「高级设置 ▾」里 max_tokens / temperature / 并发 / PDF DPI / 页数上限，改动即时保存。

界面上固定整页识别、收起了所有 API 配置项——但服务端接口（/api/run、/api/check）仍接受自定义模型配置和 mode:"region"，程序化调用的进阶玩法没砍。

两个版本：带模型的和不带的

  • 主 App：内置 1.7GB 模型，拷走 app/ 整个文件夹到任何装了 llama.cpp 或 Ollama 的机器就能跑，默认端口 8790；
  • mini/：同一套界面与功能、不带模型，整目录约 3MB，自动接入你本机已有的 xiaomi-ocr-0，默认端口 8791，跟主 App 互不打架。

换电脑迁移实测过：全新目录、全新进程，模型探测、样例、OCR、导出全部正常；孤儿进程清理依赖 lsof，Windows 缺失时自动跳过。

至此这台机器上的文档 OCR 链路彻底闭环：模型是本地的、运行时是本地的、界面是一键的——PDF 丢进去出 Markdown，全程不出本机，一分钱 API 费不花。模型本身为什么 0.8B 能越级，看上一篇 Xiaomi-OCR-0 简介。
