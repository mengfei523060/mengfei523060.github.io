Xiaomi-OCR-0：0.8B 越级打分的文档 OCR 小模型

编程2026-11-26

OCR 这事早就不必装 Tesseract 再调半天参数了。小米研究院（SeerRay-Lab）九月底开源的 Xiaomi-OCR-0 是个 0.8B 的 OCR 专用多模态模型，Apache-2.0 协议：一个模型同时吃文档解析（整页转 Markdown，表格、公式照原样还原）、图片问答（对着一页纸问数、问表、问图）、关键信息提取（给个 JSON schema，收据发票直接出结构化数据）三类活。

成绩有多越级

  • 文档解析三大榜：Real5-OmniDocBench 95.24（第一），OmniDocBench v1.6 96.83、Wild 87.94（均第二）——压过的对手普遍在 0.9B~1.2B；
  • OCR 图片问答五项平均 83.2，用 0.8B 打赢 Qwen3.5-2B 的 80.9，接近 4B 水平；
  • 公式识别 97.84、表格 92.27；手写推导、行草《千字文》都能顺下来，古籍书法项和 Seed 2.0 Pro 打平；
  • 扫描件、拍照、歪斜页这些「再拍一遍」的脏活也稳，不是只吃干净截图的榜架模型。

为什么 0.8B 敢打 2B

秘诀不在参数在数据：从 Qwen3.5-0.8B-Base 出发，用约 1.7 亿条 OCR 语料做三阶段训练——文字锚定对齐、OCR 持续预训练、再加可验证奖励的混合任务强化学习（技术报告）。标注靠 PaddleOCR-VL、MinerU、GLM-OCR 等一票专家模型投票互验，错处渲染回图里再抓。专业的事喂专业的数据，小模型就够了。

本机怎么跑

生态铺开很快：官方有 transformers 用法，社区有 GGUF 量化（llama.cpp / Ollama BF16 约 1.8 GB）、Mac 的 MLX 版、甚至端侧 LiteRT 和 ONNX int4。我机器上走的是 Ollama + 官方 MCP 服务这条路：

ollama pull longwayxu/xiaomi-ocr-0:bf16   # 模型按需加载，平时不占内存

配好后 Agent 侧直接多出一组工具：ocr_image（整页 / region 双模式，region 先版式检测切块再并发 OCR）、ocr_pdf（PDF 逐页转 Markdown）、kie_image（按 schema 出 JSON）、vqa_image（对图提问）。文档丢给 Agent 就出 Markdown，全程不出本机。

和 Strata 正好分工：大模型负责聊和写，0.8B 的专职小模型负责看文档——各干各的活，全都本地化，一分钱 API 费不花。
